# Persistent conditional entries — 0.16.2

Versioned future packets contain public entry prerequisites and possibilities alongside their selected horizons. They contain no current-scene ledger. Previously, scene-age policy still stripped those public entries after three or four accepted replies, leaving only the wider horizons even when the full conditional bridge remained useful.

The complete versioned packet now persists across accepted appends while its same-chat source prefix and references remain valid. Background review cadence is unchanged. Failed, late or stopped reviews preserve the usable packet. Successful reviews renew access and keep, revise or withdraw the selected future against accepted progress, refusal and changed circumstances. The planner contract now explicitly reviews the unfinished remainder instead of re-offering steps already taken or finished. Routine pauses and reply count alone do not expire an undertaking.

Private local activity stays private. Historical scene-facing preparations retain their existing age limit and horizon-only fallback. Archived horizon-only packets remain readable and authenticate with their original serializer; current policy can recover their complete source-verified conditional bridge. No saved chat or accepted prose is rewritten. Source edits, changed references, invalid selections and withdrawn routes still fail their existing checks. This adds no planner request and no generation wait.

Regression coverage exercises twelve accepted replies with failing reviews, preview, reload, regeneration, old horizon-only caches, pending and stopped reviews, progress updates, refusal, lost access and closure. Legacy expiry and exact cache authentication remain covered. Release versions and transitive browser imports are updated together.

The complete `npm test` suite passes: **1,188 tests, zero failures**. The installed extension is updated through Git from the source repository. Browser code requires a refresh to adopt the new retention policy.

These checks establish packet retention and lifecycle behavior. They do not guarantee the model's semantic judgment on every review. The preceding isolated multi-turn model check failed at the provider boundary, so it supplies no successful follow-up evidence about prose quality or semantic freshness. No live conversation was changed for this release.
