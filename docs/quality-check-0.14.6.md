# 0.14.6 replacement check — 2026-09-15

## What is actually different

History was reviewed, including `a7bce31` (multi-horizon planning), `9dd5a37` (offscreen simulation), `02ece9d` (writer pacing), `b7633ec` (persistent preparation), and `62e957f` (lean routine planning). Persistent, multi-horizon preparation is not a new idea here. The replacement removes mandatory actor forms, audits, scene classifications and next-reply entry instructions from generated work instead of adding another board.

Every new pass returns one contract: an RP-specific approach and persistent directions with playable middles and alternative futures. The final candidate does NOT generate factual memory, scene recaps or an overview; early experiments did, and those additional recaps repeatedly copied factual errors. Existing factual memory is preserved as input. Planning is Off on every tier; only provider-required compatibility can fall back to Low. The writer's settings are untouched. There is no critic or generated repair pass. Legacy proposals are archived on migration, not recycled as restrictions.

Ordinary appended dialogue does not expire the brief. Source edits, foreign chats and changed author inputs are checked separately. Rapid input coalesces into one running job and one latest follow-up. New completions do not rewrite already selected in-flight packets or overwrite newer factual state.

## Failures found and addressed

1. A legitimate adventure pivot changed five records and hit the old four-update validator. Update capacity now matches the twelve-record notebook; a regression covers simultaneous retirement and replacement.
2. A usable life-sim plan omitted a status. Missing status now defaults to a proposal, never active or established; an invalid supplied status still fails validation.
3. A life-sim redirection reached the writer, but a saved entry note replayed an earlier pause/question. New records no longer generate or inherit entry instructions. Focus is ordered by importance so a tight packet prioritizes the changed direction.
4. Early existing-chat replays repeated a wrong headcount and uncertain action completion; legacy proposals also kept preparation narrow. Evidence handling and migration were revised. Those runs are failures, not hidden successes.
5. A country-to-family replay invented a past player promise during a time skip. The general agency rule now explicitly covers invented past choices, not just current dialogue.
6. The replay harness passed a nested card object to a flat-reference prompt builder. The planner consequently lacked the card description. This is a test-harness error, not proof that the browser discarded the card. The harness now mirrors the browser's bounded reference fields, and fictional scenes supply their broad scenario description. Three regressions cover this. Earlier replays remain listed with this limitation rather than being presented as faithful browser comparisons.
7. A corrected-card replay proposed a player-character backstory and made one investigation the whole RP's theme. Input now explicitly identifies the player-controlled side; the approach instructions distinguish broad card/user intent from current scene observations. This removed that particular player-backstory proposal in subsequent runs, but did **not** reliably solve scene overfitting.
8. Removing generated factual recaps required preparation-only results to count as completed work. Freshness, retry-cache eligibility and automatic no-op checks now support this without treating missing recap fields as an empty failed state. Frozen legacy retry behavior remains covered.

## Acceptance boundary

One successful sequence is a smoke test, not proof of long-term quality or superiority over every preset. Synthetic forty-turn persistence checks prove retention, not forty turns of engaging prose. Existing presets can still cause invented player posture, excessive status panels, date inconsistencies or other factual drift. No universal compliance or flawless recall claim is supported.

**Not accepted as “working as advertised” yet.** The current actual-chat result still fails breadth and stale-guidance checks. Structural validity, persistence and a successful explicit pivot are necessary but insufficient. The installed extension remains unchanged at 0.14.5; no chat/settings were written, and no server restart or browser reload was performed. The user requested publishing this candidate despite these known limitations. Additional diagnostic findings are recorded below when verified.
